p_00087 — Overdraft FAQ FAQ
/personal/checking/overdraft-services/faqs
No structural gain at all — zero headings in either format The FAQ page uses accordion <div> toggles, not semantic heading tags. Markdown output is essentially identical to plain text: no # markers, same concatenation bug (QuestionsWith), same wall of paragraphs.

This confirms that the heading-concatenation issue on p_00087 is an extraction problem (accordion HTML structure), not a format choice. Switching to markdown wouldn't help this page.

Findings

What markdown gives you

  • Reliable heading markers on pages that use semantic HTML (education articles, product pages). Education articles get # / ## / ### that map perfectly to topic boundaries. Product pages get ## / ### for sections and benefit cards.
  • Bold markers on dollar amounts, key terms, and product names — useful signal for identifying factual content in product pages (22 bold spans on the Sapphire card page).

What markdown breaks

  • Bullet lists degrade. On 2 of 5 pages (p_00091, p_00131), markdown lost bullets or mangled them by gluing category labels into the first item. Plain text had cleaner list structure.
  • Word count drops. p_00091 lost 103 words (16%) in markdown mode — trafilatura's markdown renderer seems to drop some content that the txt renderer keeps.
  • Spacing artifacts. Bold markers run into adjacent text without spaces (**$500+**in qualifying), which would confuse downstream parsing.
  • FAQ/accordion pages get nothing. Pages built with <div>-based accordions produce zero heading markers in either format.

The concatenation bug is format-independent

"Frequently Asked QuestionsWith..." appears identically in both txt and markdown output for p_00087. "NEW$250" appears identically in both for p_00005. Switching output format doesn't fix these.

Recommendation

Switch to markdown — but only for the heading markers, and compensate for the list regressions.

The heading markers are the key win. They replace the current heuristic-based heading detector with explicit structural signals from the HTML. Concretely:

  1. Switch output_format to "markdown" in src/extract.py.
  2. Update the chunker to split on ^#{1,3} lines as primary chunk boundaries instead of the current is_heading() heuristic. Fall back to the heuristic for pages with zero markdown headings (FAQ/accordion pages).
  3. Post-process markdown artifacts: strip bold markers (**) from the text before chunking — they add noise for QA but their structural signal (identifying heading lines) has already been consumed.
  4. Verify no content loss: run word-count comparison across all 290 pages. If markdown consistently drops >5% of content on product/checking pages (like p_00091), consider a hybrid approach: use markdown for heading detection only, but keep the txt body.
Hybrid alternative (lower risk) Extract each page in both formats. Use markdown solely to identify heading line numbers, then apply those boundaries to the plain-text version. This gets the heading structure without any of the list/content regressions. Slightly more code, but no risk of content loss.
